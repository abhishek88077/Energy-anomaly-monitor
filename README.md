# Outlier Detection Framework for Advanced Decision Support and Business Analytics Applications

Dataset: Hourly energy consumption data (`PJME_hourly.csv`).

## What is implemented

This project adapts the uploaded KDRF paper's core idea to hourly energy consumption:

1. Data cleaning and hourly resampling
2. Contextual time features
3. Knowledge-inspired robust screening for training windows
4. Reconstruction model (portable MLP autoencoder)
5. Normalized reconstruction residual score (nRRS)
6. LOF density score (nLDS)
7. Second LOF fitness weighting
8. Unified Anomaly Score (UAS)
9. Event classification and decision-support recommendations
10. Automated test cases, including known synthetic anomalies

The main executable intentionally does **not** import PyTorch, so it works around common Windows `c10.dll / WinError 1114` installation problems. A future optional LSTM module can be added once a working PyTorch environment is available.


## Deploy to Render

This repository includes `render.yaml` and a Render start command that uses a project-local dependency directory. This avoids runtime PATH differences between Render's build and deploy phases.

1. Push the project to GitHub.
2. In Render, choose **New +** -> **Blueprint**.
3. Select the GitHub repository and deploy the detected `render.yaml`.
4. Wait for the health check at `/api/health` to pass.

The deployed website uses the real `data/PJME_hourly.csv` file committed to the repository, or a user-uploaded CSV through the dashboard. No synthetic data is generated by the web API.

## Put the real dataset here

```text
data/PJME_hourly.csv
```

The CSV should contain `Datetime` and `PJME_MW`.

## Run all tests

```powershell
pytest -q
```

## Run the real dataset

```powershell
python -m src.pipeline --data data/PJME_hourly.csv --value-col PJME_MW --epochs 80 --window 24 --stride 6 --output results
```

For a quick first run:

```powershell
python -m src.pipeline --data data/PJME_hourly.csv --value-col PJME_MW --epochs 20 --window 24 --stride 6 --output results
```

## Outputs

- `results/anomaly_scores.csv` — all windows and scores
- `results/decision_support.csv` — detected anomalies ranked by UAS
- `results/run_summary.json` — run configuration and counts

## Test cases

The test suite covers:

- duplicate timestamp handling
- missing-hour interpolation
- feature creation
- sliding windows
- invalid inputs
- robust normal screening
- min-max normalization
- local spike detection
- local drop detection
- sustained/global anomaly detection
- complete end-to-end detection using synthetic anomalies
